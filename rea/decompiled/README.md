# REA / Wakaru derived renderer sources

These files are generated by REA 6.3.0's `recover_javascript_sources` MCP tool using the pinned Wakaru 1.13.0 Linux x64 binary. They are readable derived JavaScript, not restored original TypeScript.

Each bundle directory preserves the original input snapshot, rewritten modules, output source maps, engine reports, extraction provenance, and a manifest with SHA256 digests. Structural recovery may retain a bundle as one module when original module boundaries cannot be detected. Runtime equivalence remains unknown. These outputs are not substituted into the executable app build.

Run `npm run rea:decompile` to build the local Linux amd64 image and recover missing bundle outputs, then `npm run rea:verify-decompiled` to verify input/output hashes, sizes, extraction range bounds, source-map format and full renderer asset coverage. Recovery runs without network access after image preparation. Inputs remain untouched.

Evidence lives under `evidence/wakaru/`. Container paths in the manifests start with `/workspace/`, which maps to this repository root on the host. Output source maps describe Wakaru's transformation, not missing upstream source maps.

## Local adapter fix and syntax correction

The container includes a narrow patch to REA 6.3.0's Wakaru report adapter: it accepts safe relative `.json` module filenames when Wakaru reports their kind as JavaScript. Embedded esbuild modules retained JSON-origin filenames despite containing generated JavaScript. All path normalization, artifact-set, provenance and extraction-range checks remain intact. `tools/rea-linux/patch-json-module-paths.mjs` and `evidence/wakaru/adapter-patch.json` record the change and before/after provider digests. The global REA installation is unchanged.

Raw recovery of `chunk-index-CPur7w6O` contains an additional inferred export list that collides with the retained shipped export aliases. A minimal rewrite-level retry reproduces the issue. `scripts/repair-decompiled-exports.mjs` generates a separate candidate under `repairs/`, removes that extra inferred list, preserves the raw output and checks syntax plus the complete shipped public export-name set. Its manifest and generated map record the derivation. This establishes syntax and export-name agreement, not runtime equivalence or export-value identity.

The PDF bundle has a second Wakaru defect: inferred naming produces two `const map` declarations in one constructor. A minimal rewrite retry reproduces it. `scripts/repair-decompiled-pdf.mjs` preserves raw recovery and creates a separate candidate replacing only that constructor with its exact shipped AST. Two differential cases cover cloning with and without transferred buffers. The final verification records both raw syntax defects and both validated candidates; no unresolved syntax failures remain. Full application runtime equivalence is still unknown.

Final coverage: 482 input renderer bundles, 534 recovered modules and 534 transformation source maps. All input and emitted artifact hashes/sizes, extraction-range bounds and source-map versions passed verification. Raw source recovery reported zero failures and zero warnings. `evidence/wakaru/verification.json` contains per-bundle coverage and the explicit raw/repair distinctions. `rea:decompile` also regenerates the two repair candidates and performs verification after recovery.
